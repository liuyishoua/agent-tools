# 图片改造

拥有实际编辑后的媒体与改动记录。它处理已有图，不把一段生成提示词当作成品。

## 明确改动契约

- 输入：真实源文件或可用附件、使用依据、目标画面、用途、需要保留的身份/商品/地点信息、可改变部分。
- 先实际查看原图，记录看得到的内容与技术问题；不能根据文件名或上游文字假装已看图。
- 区分编辑目的：构图与排版、光线与色彩、清理背景、场景变体、人物风格或内容替换。
- 从任务事实中列出“不可变项”和“可变项”。例如衣服可换但人物身份不变；背景可换但商品瑕疵不变。
- 已有使用授权就继续执行；来源不明的素材可作为研究参考，发布成图改用有依据的源图。

## 选择编辑方法并实际执行

1. 裁切、缩放、排版和格式转换优先使用已有图像处理工具；AI 场景或语义编辑用可用的参考图编辑工具。
2. 给工具源图与具体修改目标。把本次变化写清，比叠加“真实自然、高级质感”更能控制结果。
3. 保留原文件，成图写入新的真实路径或附件，不覆盖唯一原件。
4. 实际调用工具完成编辑；工具不可用时报告所缺能力，不给虚构文件名、附件ID或“已处理”的结论。
5. 查看输出并与源图对照；检查边缘、遮挡、光影、文字、人物一致性与物品细节。
6. 有缺陷时针对该缺陷修复。对输出连续编辑前复查不可变项，避免越修越偏离原图。

## 不同用途的关键检查

- 人物照：脸、发型、体形比例与身份参考一致；允许任务明确要求的风格变体，不能顺手换成另一个人。
- 商品图：修图不能去掉瑕疵、替换配件或改变颜色来虚构本件状态；示意图在内部独立记录。
- 地点图：作为具体地点事实依据时不增加不存在的地标或通路；纯氛围改编使用对应的叙述范围。
- 生活氛围图：视角、透视、接触点、阴影与天气一致；不能用局部锐化掩盖整体空间错误。
- 加字图：文字必须正确、可读且处在合适留白，不能只按提示词推断已经生成成功。
- 保留原作者要求的署名与用途限制；合成/编辑记录在内部 media，平台公开标记交给平台 Skill。

## 输出

返回 media 与 edit_log，可并入 ContentPackage.media。

```json
{"media":[{"attachment_id":null,"source_url":"原始页面或null","viewed":true,"role":"本次用途","internal":{"origin":"edited","source_ref":"源文件或附件","usage_basis":"实际依据","changes":["实际修改"],"preserved":["实际保留"]},"path":"实际成图","origin":"generated","usage_rights":"实际依据","generated_label_required":false}],"edit_log":{"tool":"实际调用工具","before_ref":"原图定位","after_ref":"成图定位","checks":[{"item":"不可变项或视觉检查","pass":true,"observation":"实际所见"}]},"open_issues":[]}
```

- source_ref、before_ref、after_ref 必须能对应真实材料；不伪造工具名称或完成回执。
- 没有查看输出时 viewed=false，不能写所有检查通过。
- 若指定改动与素材事实冲突，交付能完成的版本并说明未完成项；不偷偷改变原任务目的。

## 示例与验收

任务：“保留这张授权人物的脸和黑色运动装，把背景改成阴天城市河岸，留出右上角文字位置。”

独有验收：逐项对照源图后，该保留的身份或实物事实仍在，且新增部分在透视、边缘与光线上融入画面。

## 账号资料边界

身份、口吻、固定视觉形象与历史由当前账号档案提供；本技能不保存专属人设。创作中的虚拟设定与现实经历分开，公开资料只作参考，不当作账号亲历。
