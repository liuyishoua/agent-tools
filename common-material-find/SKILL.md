# 图片素材搜寻

拥有视觉候选清单与 EvidencePack。context.persona 只提供审美与身份边界；图库人物不自动成为账号主人。

## 把主题改成视觉需求

- 输入：内容主题、图片用途、构图与比例、关键可见元素、期望氛围、需要避免的元素、使用方式。
- “周末徒步”过宽，拆成主物体、动作、环境、光线和留白需求，例如“阴天石阶，路边树影，竖图，适合无人物首图”。
- 确认是在找主图、补充细节、参考图还是可编辑底图；各自的使用依据和分辨率要求不同。
- 有主人授权素材时先检索其目录，缺哪种画面再联网；不为了新鲜感抛弃已有合适素材。
- 需要同一人物时明确身份约束，不从不同图库找几个人拼成“本人连续生活”。

## 搜索、查看、核实

1. 使用本轮可用的图片搜索、网页搜索或素材 MCP，组合中英文视觉词与场景词；不绑定单一图库或服务。
2. 候选可来自主人素材、开放图库、摄影者授权页或明确可用的公共资料；社交媒体图片通常只作研究参考。
3. 打开原始素材页面，区分图片页面与聚合转贴。记录作者/机构、原页面、媒体地址、尺寸和实际许可说明。
4. 用可用图像工具实际查看候选。按画面与用途筛选，不能按网页标签、“高赞”或搜索缩略描述直接通过。
5. 比较视觉重点、主体遮挡、可裁切空间、色温、清晰度和同组协调性。优先少量可用候选，不堆链接。
6. 需要修改时说明具体可改造部分，如去除背景杂物或补留白，并把源图交给 common-material-edit。

## 使用依据与失败处理

- 记录本次实际依据：主人授权、具体许可页面或许可人信息；“能下载”“没有水印”“注明来源”不等于可复用。
- 许可不清的好图可留作视觉参考，不能默认为发布素材；继续找有依据的替代品。
- 不绕过图片防盗链、登录或下载限制；优先使用工具已有可见图片、授权素材或更换来源。
- 下载成功不等于已查看；没有查看工具时交付待验候选并明确 viewed=false，不称已验收。
- 人物、商标或场所的限制按实际用途判断，不将某次项目限制变成所有素材通用禁令。
- 必须履行的署名保存在使用要求，交给平台适配层落实，不擅自删掉。

## 输出

返回 candidates 与 source_refs（EvidencePack 条目）；本 Skill 不负责写最终帖子。

```json
{"candidates":[{"source_url":"原始素材页","media_url":"可用媒体地址或null","author":"作者或null","dimensions":null,"role":"首图/细节/参考","viewed":true,"visible":"具体可见内容","fit":"为何合适","required_attribution":null,"allowed_use":"publish|edit|reference|unknown","edit_suggestion":null,"path":"实际本地文件或null","origin":"owner|licensed|generated","usage_rights":"授权或许可依据","generated_label_required":false}],"open_issues":[],"source_refs":[{"source_url":"素材/许可页面","published_at":null,"accessed_at":"实际时间","observations":["许可与画面核实"],"usage":"来源与用途依据"}]}
```

- 未获得的文件、分辨率、许可或日期填 null/unknown，不能补造。
- 原作者照片中的地点可作来源线索；没有核实就不能成为最终正文的精确定位。
- 如果没有可用结果，报告尝试过的检索方向和具体缺项，避免交出名义可用的陌生人自拍。

## 示例与验收

任务：“找两张适合雨后散步笔记的竖图，要树影和湿路面，能合法复用或编辑，不需要人物。”

独有验收：每张推荐图都实际看过，并能回答原图在哪、看到了什么、为什么适配、凭什么可用于本次用途。

## 账号资料边界

身份、口吻、固定视觉形象与历史由当前账号档案提供；本技能不保存专属人设。创作中的虚拟设定与现实经历分开，公开资料只作参考，不当作账号亲历。
