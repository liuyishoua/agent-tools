# 工作台页面保留约定

侧栏和页内标签切换应优先复用已打开页面，避免重新生成整页或重复显示加载状态。首次进入仍按需加载。当前缓存只属于当前浏览器窗口中的运营用户和平台账号，不能把完整业务页面或凭据持久化到浏览器存储。

## 实现边界

- 保留输入、未提交内容、筛选、展开项、页面与列表滚动位置，以及原组件事件绑定。
- 监听和任务回执持续取最新数据；隐藏页面暂停界面轮询，回到页面后恢复。缓存不代替后台任务状态。
- 成功写入后使其他未编辑页面缓存失效；未提交表单保留。显式刷新重新读取数据。
- 切换运营用户或平台账号时清空相应缓存。旧请求不能覆盖当前账号界面。
- 以工作台标签为缓存单位，限制缓存数量，避免每个查询字符串创建一份页面。新增编辑页时同时检查生命周期和数据更新。

| 抖音发送 | 保留页面和对应轮询生命周期；切回恢复当前状态、输入与历史导航 |
| 应用中心 | 保留实际 AI 对话组件、未发内容和目录筛选；隐藏对话暂停查询；运营用户变化清空 |
| 经营目标、Channel | 保留标签 DOM；相同数据不重建内容；变化时更新数据并恢复控件、焦点、展开与滚动 |
| 票务、账号中心 | 已采用隐藏面板切换，验证了现有 DOM 与筛选保留，无需替换 |
| Multica | 已有 Query 缓存、草稿状态与会话清理机制；本次仅检查现有实现，未修改 |

五个内容工作台的缓存保存在各自原生入口内。抖音运营、经营目标与 Channel 使用各自静态目录内的 `page-cache.mjs`，便于独立部署，不跨项目读取运行配置。

## 验证

- `account-maintenance/.venv/bin/python agent-tools/tests/browser/workspace_tabs.py`：逐个启动五个临时 DemoPlatform 服务，验证原 DOM、未存草稿、恢复后的保存处理、历史导航、账号清空与手机布局。
- `account-maintenance/.venv/bin/python agent-tools/tests/browser/workspace_cache_mocked.py`：只由本地构建和合成 API 响应验证小红书、应用中心、两套抖音、经营目标、Channel，以及现有票务和账号中心。不会发出真实消息、发布内容或启动真实任务。
- 小红书继续执行 `tests/browser/multitab_identity.py`；应用中心继续执行 `tests/browser/startup_check.py` 和 `rich_chat_check.py`。
- 各工作台的既有服务端回归及前端语法 / TypeScript 构建保持通过。

前端资源发布后，已打开的浏览器需要刷新一次才加载新实现；缓存随刷新清空。接口错误保留明确提示和重试，不把旧状态当作新的平台回执。
