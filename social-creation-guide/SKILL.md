# 经验与攻略

拥有可执行知识主导的 ContentPackage。账号观点来自 context.persona，经验归属来自任务记录；资料整理不自动写成本人亲测。

## 输入与证据

- 输入：读者要完成的行动、地点或物品、已确认经验、使用条件、篇幅与本轮素材。
- 先说清适用对象和关键限制，例如“下班有两小时、公共交通、少爬坡”；比先凑十大推荐更能决定内容。
- 把资料分成本人确认、可靠外部事实、个人判断与未确认。给每个会影响行动的结论找依据。
- 门票、营业时间、交通、开放状态、规则和近期路况属于动态事实，本轮实际检索官方或直接来源。
- 距离、耗时、费用和难度写明依据与适用条件；没有测量依据时用估计范围，不能给虚假精度。

## 围绕真正的决策写

1. 找出读者最容易卡住的一步：选入口、换乘、找回程、决定带什么，或判断是否适合自己。
2. 按行动顺序写必要信息，优先回答这一步。可以有路线表或对比，但不强制统一模板。
3. 路线类检查起点、转折、终点与回程是否连接；真实地图或官方资料没有的连接不靠想象补齐。
4. 装备类说明使用场景、取舍和限制；分清实际使用体验与规格资料，不写无依据的“闭眼入”。
5. 经验类保留能改变做法的细节，例如哪个口出站更少绕路；删除不影响行动的空洞形容。
6. 交付前模拟一次读者行动，检查文中是否存在“照着做却做不下去”的信息缺口。

## 让信息仍像这个账号说的

- 人设影响优先级：爱省事的账号会先写回程，爱拍照的账号会说光线；不能让口吻掩盖条件与限制。
- 已确认个人经历可用第一人称，公开资料用介绍、整理或建议语气，不制造“踩坑才知道”。
- 允许承认取舍：“更好拍，但得多走一段”比全都“绝美、轻松、必去”有用。
- 配图服务于决策：入口、岔路、物品细节或路线图。装饰性风景不能替代关键说明。
- 需要新增媒体时调用实际工具并查看；示意图与实物图在内部清楚标识，避免混用成事实证据。
- 不为了增加“人感”删除必要条件、单位或原始来源。

## 输出

返回 ContentPackage，外部研究随附 EvidencePack。

```json
{"title":"","body":"","media":[],"source_refs":[{"source_url":"直接依据","published_at":null,"accessed_at":"实际时间","observations":["核实的事实"],"usage":"支持哪条行动信息"}],"claims":[{"text":"可执行结论","basis":"任务记录或来源URL","status":"confirmed|estimate|uncertain","kind":"verified_fact|preference|creative"}],"quality":{"status":"ready|hold","observations":[],"missing":[],"audience":"适用人群","action_gap":[],"dynamic_facts_checked_at":"实际核对时间或null"}}
```

- 页面未标日期就 published_at=null，不能把访问日期当发布日期。
- 动态信息核实失败时移除不可支持的确定表述或写清当前未确认项，保持可用的其余内容。
- 平台篇幅不够时保留关键条件，可删感受，不截断行动步骤。

- 统一 ContentPackage：media 使用 path/source_url/origin/usage_rights/generated_label_required/viewed，claims 包含 text/basis/kind，quality 包含 status/observations/missing；检查完成且无缺项才 ready，否则 hold。

## 示例与验收

任务：“给只想走平路的人整理一个两小时城市步行方案，说明怎么到、哪里结束、哪些信息还要现场确认。”

独有验收：读者能从起点走到终点并安排离开，文中的每个关键数值与动态条件都有可追溯依据。

## 账号资料边界

身份、口吻、固定视觉形象与历史由当前账号档案提供；本技能不保存专属人设。创作中的虚拟设定与现实经历分开，公开资料只作参考，不当作账号亲历。
